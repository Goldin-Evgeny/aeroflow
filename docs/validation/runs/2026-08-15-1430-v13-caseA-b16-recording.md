## 5. Anomalies — stated plainly, not diagnosed

### 5.1 q moved **down** against the pre-repair reference at this resolution

|                                                                                         | q at 16 cells/b |
| --------------------------------------------------------------------------------------- | --------------- |
| Pre-repair reference (M10 resolution-convergence story, cited at `aij.gpu.spec.ts:118`) | ≈ **0.532**     |
| This run, post height-mapping repair                                                    | **0.476**       |

A shift of **−0.056** (−10.5% relative). The direction is _away_ from the gate. This is a
recorded observation, not a verdict — the band does not apply here — but it is the opposite
of what "corrected mapping" would naively predict, and it is the first number in this change
that lets the height repair be compared against a same-resolution predecessor.

Two things this does **not** establish: whether the pre-repair 0.532 was measured on GPU or
CPU and under what tree state, and whether the shift is the height repair alone or any of
the other 74 dirty-tree entries. Neither was checked.

### 5.2 The resolution-convergence pair now reads 0.476 → 0.659

Against b=24's last windowed q of 0.659 (from the 13:27 run, which **never reached steadiness
and returned no verdict**). The pairing is therefore between a _converged_ low-resolution
recording and a _non-converged_ high-resolution sample, and the second half is not a
measurement. The convergence direction is strongly positive with resolution, consistent with
the standing story that the acceptance resolution is 24 — but the pair cannot be quoted as a
convergence result until b=24 converges.

### 5.3 The harness's config readout was not captured

A passing test writes no page snapshot and no `test-results/` artifacts, and the AIJ page
emits no JSON of its own, so §2 could not be filled in verbatim the way the 13:27 run's could.
Only the test's own attachments survive. This is the same gap recorded as anomaly 7 of the
13:27 run, now demonstrated from the other direction: that run's config survived _because it
failed_.

### 5.4 Two prior executions of this identical run were lost to output filtering

The same test ran twice before this one and passed both times, and both results were
discarded before reaching the record:

- The first was invoked with `--reporter=list`, which **replaces** the config's
  `[['list'], ['html']]` rather than adding to it — so no HTML report was written, and a
  passing test writes no `test-results/`.
- The second used the config's reporters, but `rtk` (a token-reducing CLI proxy active on
  this machine, `rtk 0.44.2`) intercepts `playwright test` and rewrites its output to a
  `PASS (n) FAIL (n) / Time: Xms` summary at 100% output reduction, discarding attachments;
  the HTML report was not produced either.

Only the third attempt, forced through `rtk proxy` with a file-writing JSON reporter,
produced a retainable artifact. **Consequence for this repo's run-history rule:** any GPU
acceptance whose results live solely in Playwright reporter output is not reliably
persistable under the default command path. Recorded here; not fixed.

### 5.5 q is quantized

`q = 0.47619047619047616` is exactly 10/21, and eight of nine windows report the identical
value while the drift statistic moves over an order of magnitude. The hit rate is a
count-over-points ratio, so it steps discretely and is a far coarser convergence signal than
the drift it is judged alongside.
