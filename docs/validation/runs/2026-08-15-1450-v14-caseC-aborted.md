## 5. Anomalies

### 5.1 The harness budget contradicts a measurement already in the repo

`apps/studio/e2e/aij-urban.gpu.spec.ts:64-66` sets `completionTimeoutMs = 2 h` for Case C,
with a comment estimating "~1.4 h on the reference RTX 3090", and `test.setTimeout(2.25 h)`.

[D1](../../decisions/D1-resolution-wall.md) records both that the 1.4 h estimate is
**falsified** (D1:135 — "~~≈1.4 h~~ — falsified by measurement 2026-07-28: ≥ 8.7 h") and
what the strict grid actually costs (D1:245 — **5.96 h**, 21,454 s, 365,560 steps, 120/120
points scored, ~3261 scene MLUPs at 97–99% duty, on this same RTX 3090).

So the test as written would have failed its completion poll at 2 h, roughly four hours
short, regardless of solver behaviour. **Task 7.7 is not executable against this harness.**
Per the project's own doctrine — stated in `aij.gpu.spec.ts`: "a timeout is a MEASUREMENT
that sets the next budget… the fix is the budget, never the gate" — the correction is to the
budget. It was not made here; no gate was touched.

### 5.2 The run's compute duty matched D1's recorded hang signature

D1's Wall-3 section describes an **intermittent** Case C hang: a healthy run holds **97–99%
compute duty**, while the failed attempt "did ~53 min of healthy work and then hung", with
steps and compute freezing together — "a stall, not slowness."

This run started at 100% duty and was at **4–8%** when sampled at ~56 min, with memory still
resident and one core busy. That is close enough to the recorded signature to have made
continuing indefensible, and it is the operative reason the run was killed rather than left
to reach its (already doomed) 2 h timeout.

**This is not a confirmed hang.** The step counter was not readable without the page, so
"stalled" versus "in a long CPU-bound scoring or checkpoint phase" was not distinguished.
D1 states the root cause is unknown, that it did not reproduce on the subsequent run, and
that no fix is claimed. Nothing here changes that.

### 5.3 The harness has no stall resilience

D1:242-245 notes the 5.96 h run that _did_ complete used a stall-resilient harness —
checkpoint-resume on a 6-minute no-progress detector (which never triggered).
`aij-urban.gpu.spec.ts` has no equivalent. A corrected ~7 h budget on this harness would
therefore still be exposed to the same intermittent hang with no recovery path.

### 5.4 No partial artifact survived the abort

`test-results/` for this test is empty and the JSON reporter file was never written, because
both are produced at test end. A run killed mid-flight leaves nothing but stdout. Combined
with anomaly 5.4 of [2026-08-15-1430-v13-caseA-b16-recording](2026-08-15-1430-v13-caseA-b16-recording.md),
the pattern is now three-for-three: this repo's GPU acceptance results survive only on the
harness's own terms, and a long run has no incremental record at all.
